# eval/fixtures

Sample inputs so `eval/score.py` runs on a laptop with nothing else built.
**None of this is a real measurement.** Replace with real runs before the demo.

| file | what it stands in for |
|---|---|
| `dev.log` | **SYNTHESIZED**, generated by `eval/make_dev_log_fixture.py`. Stands in for `build/livekit/dev.log`, which `unmute dev` writes. Sentinel-prefixed JSON records plus plain log lines, because the real file is the worker's stdout and carries both. |
| `runs.json` | maps each `call_id` in the log to the `eval/prescriptions.csv` row it was a run of. Generated alongside `dev.log`. The real one is written by whoever drives the 30 runs. |
| `teachback_cases.json` | the 5 deliberately-wrong read-backs for the catch-rate number, plus a 6th CONTROL case that is correct. |
| `halfstep_cases.json` | half-step renders, dose-word parses and teach-back cases, run in all three languages. The suite docs/00 §7's two silent bugs cannot survive. |
| `review_sheet_filled_sample.csv` | a *sample* of what a native speaker hands back, so `score.py score` can be exercised. The verdicts in it are invented — they are not a translation-accuracy result. |

## `dev.log` is not a recording, and must never be read as one

No live turn has ever run (docs/00 §3, §12). There is nothing to record yet.
Every record shape in the file comes from the **generated emitter**,
`vaidyavaani-agent/build/livekit/utils/dev_metrics.py`, documented in docs/03
§14 — the emitter is what writes the real log, so the shapes are authoritative.
The **timings are invented** and the **order of records is a plausible guess**.
Which records a real VaidyaVaani turn emits, and in what order, is still one of
the open items in docs/00 §12.

The file carries that warning in its own header, and `score.py all` prints it
in red at the end of every run while `--log` still points here. Nothing taken
from it belongs on a slide.

## It is a derived artifact — regenerate it, never hand-edit it

The spoken strings in `dev.log` are the template render of the **real**
`content/readback/*.yaml`. A hand-written copy goes stale the moment a native
speaker corrects a string, and the harness then reports "deviations" that are
nothing but the fixture rotting. docs/00 §6 records exactly that costing two
round trips, on a diagnosis that was wrong in both directions.

```bash
python3 -I eval/score.py fixture-drift      # fails loudly if this is stale
python3 -I eval/make_dev_log_fixture.py     # rewrite dev.log and runs.json
```

`fixture-drift` runs inside `score.py all`, so drift cannot pass unnoticed. It
also fails if anything that looks like a copy of a content template appears
under `eval/` at all.

## The seeded deviations

A fixture where everything passes proves only that the harness prints "pass",
so two deviations are seeded:

* **`rx-07`, all three languages** — the agent paraphrases the notes clause
  rather than reading it verbatim. `notes` is the one free-text field in the
  rendered sentence, so it is the one an LLM is most tempted to reword.
* **`rx-01` in Tamil** — the same sentence in NFD with a doubled space:
  byte-different, meaning-identical, and the only case exercising the
  difference between the strict and the normalised count.

Expected result: **26/30 byte-identical, 27/30 after NFC, 3 deviations
reported, 30/33 confirmed lines verbatim, exit 0**. docs/02 §1.4 commits us to
reporting a deviation, not hiding it behind a pass.

## How a read-back utterance is identified

**There is no `task` field in a real dev.log, and no `kind: "transcript"`
record either** — an earlier version of this harness looked for both and would
have matched nothing. The emitter writes spoken text as `kind: "text"` with
`speaker: "assistant"`, and one utterance can arrive as several segments
sharing a `message_id`.

What the log does carry is the gate's `readback_text` landing in the agent's
state as a `kind: "state"` record, so **anything the agent speaks after that
point is the read-back**. If a real log turns out not to carry state records,
`score.py --loose-task-match` falls back to the agent's last utterance in the
call and says in its output that it did so.
